# Самопроверка

Работа идёт в порядке из дополнения к заданию: Ansible настраивает готовую VM, затем Terraform создаёт ресурсы Docker. На выданном сервере Ubuntu 24.04, playbook также рассчитан на 22.04.

Проверены повторный запуск Ansible (`changed=0`), Terraform validate и plan после apply (`No changes`), HTTP на 8088 и через reverse proxy. Все три контейнера healthy. У Nginx от Terraform отдельная сеть и именованный том, Compose работает в своих сетях. Вывод команд сохранён в [evidence/remote](evidence/remote).

Мониторинг проверен на Docker и временном сервисе, который завершался с ошибкой. Восемь тестов прошли на Mac и VM. Скрипт считает строки с ключевыми словами только в текущем syslog, поэтому записи из архивов после ротации в счётчик не попадают.

Что нужно учитывать при повторном запуске:

- Вход на VM — по отдельному ключу. При смене исходящего IP нужно обновить UFW.
- У deployer полный sudo без пароля, как требуется в задании.
- State и ключи не входят в Git; резервные копии нужны отдельно.
- Провайдер установлен из GitHub-релиза с проверкой SHA256, потому что Registry возвращал 404. Lock-файл рассчитан на Linux AMD64.
- Образ Nginx закреплён тегом версии, а не digest.
- `terraform destroy` удалит том с данными вместе с остальными ресурсами Terraform.

Код слит в `main` через [PR №1](https://github.com/ognevde17/devops/pull/1), на merge-коммите создан тег `v0.1.0`.
